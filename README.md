# 女仆建筑 / MaidConstruction

![Build and Release](https://github.com/ly-ina/MaidConstruction/actions/workflows/release.yml/badge.svg)

Minecraft Forge 1.20.1 模组。参考机械动力的蓝图，做一张可以反复使用的「图纸」：

**框选记录建筑 → 拿着它投影到任意位置 → 交给车万女仆按图施工。**

蓝图只是图纸，**不能一键放置**，建造全部由女仆完成。

> **要改代码或扩展功能？先读 [DEVELOPER.md](DEVELOPER.md)。**
> 里面有架构说明、四条主链路的完整数据流、扩展点指南，以及一份「改这里会踩坑」的清单。

---

## 功能

- **框选录制**：拿蓝图点两个角点，把区域内的方块（含朝向、方块实体数据）完整记录下来
- **实时投影**：手持蓝图时，结构以半透明幽灵方块跟着视线显示，已建成的部分自动隐藏
- **任意定位 / 四向旋转**：右键方块钉住位置，右键空气每次转 90°
- **蓝图面板**：Shift + 右键空气打开，可拖动查看 3D 预览、旋转、清空、导入导出
- **女仆施工**：女仆走到结构外站定，逐块砌完；缺料自动去容器取，建完把剩料还回去
- **绑定书**：把远处的仓库（或 ME 网络）指定成专用取料点，还能一键高亮位置
- **容器兼容**：任何对外暴露标准物品栏能力的容器都能取料，包括 ME 网络的终端
- **创造女仆接口**：取之不尽的物品来源，女仆绑定即可无限取料；接上 ME 网络后全网都能取到任意物品
- **无线女仆终端 / 女仆绑定卡**：女仆饰品，装上后她不必跑回 ME 网络就能取料；带上绑定卡后，女仆取料也不再看距离与维度

## 使用方法

### 蓝图

合成蓝图：8 张纸 + 玻璃板。

| 操作 | 效果 |
|---|---|
| 空蓝图 + 右键方块 | 选定第一个角点 |
| 空蓝图 + 再右键另一个方块 | 完成框选，服务端扫描并记录 |
| 空蓝图 + Shift + 右键方块 | 清除选点 |
| 蓝图 + 右键方块 | 锚定投影位置 |
| 蓝图 + **右键空气** | **旋转 90°**（0° → 90° → 180° → 270°） |
| 蓝图 + **Shift + 右键空气** | **打开蓝图面板** |

蓝图有两个形态，物品名会跟着变：**空白蓝图** ⇄ **蓝图**。已完工的蓝图 tooltip 会显示「目标建筑已完工」。

### 绑定书

合成：书与笔 + P 点（需要车万女仆）。

用来告诉女仆「东西放在哪」。女仆取料时**优先搜身边 10 格**，附近实在找不到，才照绑定书跑一趟远处的仓库。

| 操作 | 效果 |
|---|---|
| 右键容器 | 绑定（记录坐标、维度、方块名称） |
| **Shift + 右键空气** | **高亮绑定位置**（呼吸线框，10 秒） |
| Shift + 右键方块 | 解除绑定 |

绑定书可以放进**女仆的饰品栏**，也可以塞进她的普通背包。绑定的是坐标而不是容器实体——箱子拆了重放照样能用。

高亮是纯客户端效果，没有网络延迟。如果目标在别的维度、或者区块还没加载，会直接告诉你原因，而不是给个永远不出现的框。

## 女仆配合

需要安装 [车万女仆（Touhou Little Maid）](https://github.com/TartaricAcid/TouhouLittleMaid) 1.5.2 以上（可选依赖，不装也能正常用蓝图看投影）。

1. 把**已锚定**的蓝图交给女仆——主手、副手、背包任意一处都认
2. 女仆的工作模式切到 **「蓝图施工」**
3. 她会自己走到结构外圈站定，然后开始建造

### 施工表现

- 每放一块都会**挥手**、**转头看向施工点**，并播放该方块的放置音效
- 材料不够时跑去容器取，箱子会**播放开合动画**
- 站在原地建完整座结构，不会被主人距离打断
- 建完播报一次，蓝图 tooltip 显示「目标建筑已完工」

### 取料规则

- **按需取料**：结构只要 5 块石头就只拿 5 块，不会把整箱掏空
- **就近优先**：先搜身边 10 格，没有才去绑定书指定的仓库
- **走不进容器也没关系**：导航目标是容器旁边的空位（不会贴着箱子蹭），实在过不去就在原地取
- **不碰装备栏**：材料只进女仆的背包，不会跑到她手上或盔甲槽

### 完工后

- **收走蓝图**：建完的蓝图自动从手上收进背包，手腾出来
- **自动接活**：背包里若还有没建完的蓝图，女仆会自己挑出来接着干——一次塞好几张，她一张张建完
- **归还剩料**：把用不完的建造材料送回容器，**优先送回绑定书指定的那个**；容器满了或找不到地方，材料会留在她身上，绝不丢弃
- **不再复查**：已完工的蓝图不会再去工地（否则拆掉几块她就会来回跑）。想重新开工，**重新右键定位或改朝向**即可清掉完工标记

## 容器与 AE2 兼容

### 通用容器

任何对外暴露标准物品栏能力（`IItemHandler`）的容器都能**取料**和**归还**：

原版箱子 / 桶 / 潜影盒、铁箱子、Storage Drawers、Functional Storage、机械动力的置物台、Tom's Simple Storage 终端、**精妙背包放下来之后的方块形态**，以及其他各类自动化 mod 的机器。

### AE2

装 AE2 时额外提供两条能力：

**1. 从 ME 网络取料与归还**

绑定书指向 ME 网络中的任意接入点即可，**存储总线、ME 接口、终端、驱动器、控制器、线缆**都认。

- 存储总线 / ME 接口这类方块自身就是存储，直接读能力
- 终端、驱动器、线缆则顺着网格节点问到整个网络的库存
- 提取前会先模拟确认背包容量，**绝不出现「提出来又塞不回去」导致物品蒸发**
- 网络塞不下时，多出来的原样退回背包

**2. 女仆终端**

专为女仆取料做的方块，**六个面都是 ME 终端面板**，右键打开的是** AE2 原版终端界面**（物品列表、搜索、排序、合成全都可用）。

```
照明面板   ME接口   照明面板
照明面板   ME终端   照明面板
照明面板   ME接口   照明面板
```

它和 AE2 自带终端的关键区别：**它是个规规矩矩的方块实体**，自己就是网格节点宿主、自己暴露存储能力。AE2 自带的终端挂在线缆上，承载它的方块会把能力查询代理给部件，外部拿到的"存储"未必是整个网络的——绑定书因此认不出来。

放置要求：**紧贴着线缆或别的 AE 设备**（节点会自动连接），网络至少有 1 个空闲频道。右键时若条件不满足会明确告诉你缺什么：

| 提示 | 缺什么 |
|---|---|
| 周围没有任何 AE 设备 | 没接线缆 |
| 没有连上任何 ME 网络 | 有邻居但没成网 |
| ME 网络没有供电 | 没电 |
| 网络频道不足 | 没频道 |

终端功耗与 AE2 官方终端一致（**为 0，不耗电**）。

**3. 创造女仆接口**

一个"什么都有、取之不尽"的方块，给测试和搭景用。它和女仆终端正好相反——终端代表的是**整张网络**，它代表的是**自己**：

| 用法 | 怎么用 | 效果 |
|---|---|---|
| 女仆创造物品栏 | 用**绑定书**指向它，女仆施工时缺什么拿什么 | 不需要任何 ME 网络，也不需要通电 |
| 全网无限库存 | 把它**贴着线缆或别的 AE 设备**放 | 整张 ME 网络"什么都能取"，任意终端里都能看到并取出游戏里的所有物品 |

右键打开的是 **AE2 原版终端界面**（物品列表、搜索、排序、合成都可用）。没接网络时界面里显示的就是它自己的创造库存，所以**永远不会是空的**；接了网络则显示全网库存。

几点说明：

- **女仆不会自动就近取它** —— 必须用绑定书指过去。否则站在旁边的普通箱子会被它抢走，行为不好预期
- **女仆的剩料会被它收下**（建完房还回来的材料在这里直接清掉，不占任何存储）；但**接入网络的那份拒收**——否则玩家往任意终端里放东西都会被静默销毁
- 联网后它仍需**通电**并占用 **1 个频道**，和女仆终端一样；不满足时右键会提示 AE 侧暂不可用，但**不影响女仆直接取料**
- 合成需要 `ae2:creative_energy_cell`（创造能量单元），所以正常生存是拿不到的

**4. 无线女仆终端与女仆绑定卡**

女仆饰品形态的 ME 终端。放进女仆的**饰品栏或背包**，她缺料时会直接从网络里取，
不必再跑回仓库那边。

| 操作 | 效果 |
|---|---|
| **右键空气** | 打开 AE 原版终端界面 |
| **放进 ME 无线访问点的槽位** | 链接（跟 AE2 官方无线终端一模一样的做法） |
| **Shift + 右键空气** | 断开链接 |

右键**方块**不会拦——照旧是方块自己的功能（右键充能器放进去充电、右键访问点开它的界面、
右键驱动器开它的界面）。**手持终端右键无线访问点，开的是访问点的界面**，跟官方终端一样。

- **怎么连上网络**：终端先要跟某张网络上的 **ME 无线访问点**链接一次。做法跟官方无线终端完全一样——
  把终端放进访问点界面里的槽位，点链接。没有访问点的网络，这台终端连不上
- **没链接就开不了面板**，右键会跟官方一样提示**「设备未链接」**；链接的那台访问点找不到时
  提示「找不到链接的网络」。这两种提示是 AE2 原生的，不是这个模组加的
- **距离**：AE2 原生终端**没有距离上限**——只要那台访问点所在的区块加载着就能用。
  距离影响的是**耗电速度**（越远越费电，插了无线增幅卡会同时扩大射程与耗电基准）
- **跨维度**：AE2 自己算不出跨维度的距离，会给一个天文数字的耗电速率（一 tick 就能把整张网络抽干），
  所以跨维度实际上用不了。插了**女仆绑定卡**之后，跨维度按**固定 22.5 AE/tick** 计
  ——这个数值取自 **AE2WTLib 的量子桥卡**，它补的就是同一个洞
- **电量**：终端自带电池，规则跟官方一样——**没电就打不开面板**（提示「设备未通电」），
  所以刚做出来的终端要先在**充能器**里充一次电（拿着终端右键充能器就放进去了）。
  插了**女仆绑定卡**之后，耗电改由 AE 网络承担，内置电池不再流失
  ——远距离和跨维度都靠这张卡才撑得住
- 女仆用它取料时**不用走到任何地方**，站在工地就取了

> ⚠️ **前提是目标区块已加载。** ME 网络只存在于已加载的区块里，
> AE2 自己也做不到隔空访问未加载的网格——远程网络那边得靠区块加载器撑着。

合成（都要求装了 AE2）：

```
无线女仆终端                     女仆绑定卡（无序）
 . L .        L = 照明面板        高级卡 + 无线增幅卡 + 绑定书
 L W L        W = AE2 无线终端
 . T .        T = 女仆终端
```

> 绑定卡用到了**绑定书**，而绑定书的合成需要车万女仆的 P 点——
> 所以**没装车万女仆时这张卡合不出来**（配方本身能正常加载，只是缺一味材料）。
> 无线女仆终端这条链则只依赖 AE2。

## 蓝图面板

Shift + 右键空气打开：

```
┌──────────────────────────────────────────────────────┐
│ 蓝图  名称 [ 城堡_________ ]         blueprints 目录   │
├──────────────┬──────────────────┬────────────────────┤
│              │  旋转 90°         │  城堡.blueprint     │
│   3D 预览     │  清空锚点         │  农舍.blueprint     │
│  （可拖动）   │  清空录制         │  ...               │
│              │  导出到文件       │  （可滚动，点击选中） │
│              │  导入选中文件     │                    │
│              │  打开文件夹       │                    │
│              │  关闭             │                    │
├──────────────┴──────────────────┴────────────────────┤
│ 状态提示                                              │
└──────────────────────────────────────────────────────┘
```

- **名称**：左上角直接改名，导出时拿它当文件名
- **3D 预览**：整个结构以等距视角渲染，**按住左键拖动可以转着看**，底部显示尺寸
- **旋转按钮**：和右键空气等效，面板里直接转
- **清空锚点 / 清空录制**：不用再靠组合键
- **打开文件夹**：直接调起系统文件管理器打开 `blueprints/`，不用自己翻路径
- **状态提示**：导入导出、打开文件夹的结果显示在面板底部

## 导入导出

文件放在**游戏目录的 `blueprints/`** 下（会自动创建），扩展名 `.blueprint`，内容是压缩过的 NBT。

- 文件名就是**蓝图名**，不加时间戳，**同名直接覆盖**——想留档就在面板里改个名字再导出
- 早期版本用过 `.blueprint.nbt` 双后缀，列表里照样认，老文件不会看不见
- 单个文件超过 1 MB 就不再导入（免得网络包撑爆）

导出的文件可以直接拷给别人，对方丢进自己的 `blueprints/` 就能用。

- **没装 AE2**：取料兼容所有普通容器；但**女仆终端**、**创造女仆接口**这两个方块，

  连里面的升级卡一起——原版对不认识的方块 id 就是这么处理的）

## 构建

需要 **JDK 17**。

```bash
./gradlew build          # Windows 用 gradlew.bat build
./gradlew runClient      # 启动游戏测试
```

产物在 `build/libs/MaidConstruction-<版本>.jar`。

Java 版本可在 `gradle.properties` 里改 `java_version`（默认 17）。

> AE2 在构建脚本里是 `compileOnly`，故意没有 `runtimeOnly`——所以 `runClient` 里不会加载 AE2，想在开发环境测 ME 取料需要自行临时加上。

## 实现要点

**数据结构**

- **结构存储**：存在世界存档的 `SavedData` 里（主世界），蓝图物品只存一个 UUID，避免物品 NBT 膨胀
- **紧凑编码**：调色板 + 索引数组，不是逐方块存对象
- **旋转**：位置重新映射；方块状态除 `BlockState.rotate()` 外，还按**原始属性值**把所有朝向属性补转一遍
  （原版 `Block.rotate` 的默认实现根本不转朝向，很多模组的机器没覆写它），方块实体 NBT 里的朝向由各自的解析器负责

**建造**

- **摆放顺序**：先完整方块打底，依附类（火把、半砖等）留到下一轮重试，避免放不下去
- **幂等建造**：已和目标状态一致的方块会被跳过，中断、重扫、存档重载都不会破坏已建成部分

**女仆驱动**

- **不走 Brain 调度**：车万女仆的 `createBrainTasks` 要经内部多层装配才会执行，中间任何一环不满足女仆就一动不动且没有报错。改成服务端 tick 里直接查找并驱动，行为完全可控
- **待命状态**：施工期间给女仆开启待命模式，避免因离主人太远被拽走；**原始状态记在女仆自己的持久数据里**（不是控制器字段），所以女仆区块卸载重载后也能正确还原
- **取料抽象**：`ItemProvider` 把「材料从哪来」和主流程解耦，普通容器和 ME 网络各自实现，加新存储类型只是加一个实现类

> 以上只是提要。完整的架构说明、扩展点步骤（怎么接一种新存储、怎么让某个方块的材料
> 或朝向计算正确），以及一份「现象 → 原因」的排查手册，都在 **[DEVELOPER.md](DEVELOPER.md)**。
